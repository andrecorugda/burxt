# Burxt — one word per concept

> Status: **in force, and tested.** `one_word_per_concept_in_the_burxt_compiler` in
> `tests/runner.rs` enforces the parts of this that can be checked mechanically.

## Why this document exists

Andre, 2026-07-29, after asking whether a function was called `find_sym` or `find_bind`:

> "please do audit, we keep on repeating this kind of inconsistent"

He was right that it kept recurring, and the audit found why. **The convention already existed.**
Four of six lookup families already followed it. Nobody had written it down, so the other two drifted
and nothing noticed.

## The rule

A concept gets **one word**, used everywhere it appears:

| | |
|---|---|
| the lookup | `find_<thing>` |
| the array it searches | `<thing>s` |
| the record it holds | `<Thing>` |
| its counter, if it has one | `find_<thing>_calls` |

```
find_method    → methods    → Method       ✅
find_slot      → slots      → Slot         ✅
find_instance  → instances  → Instance     ✅
find_type      → types      → TypeDeclaration
find_binding   → bindings   → Binding      ✅ since v0.0.122
find_function  → functions  → DeclaredFunction  ✅ since v0.0.122
```

## What the audit found

**`find_sym` searched `self.syms`, which held `Binding` records, and incremented
`find_binding_calls`.** Four names for one concept, in one function, three of them visible in a
five-line body:

```burxt
function (mutable self: Unit) find_sym(src: String, start: Int, length: Int) -> Int {
    self.find_binding_calls += 1;
    ...
        if spans_equal(src, self.syms[i].start, ...
```

And `find_fun` searched `self.funs` while its counter said `function` and its record was
`DeclaredFunction` — so `fun` and `function` both meant function, in adjacent lines.

**`Binding` won** over `sym`/`symbol`, and not by coin toss. It is what the thing *is*: a name bound
to a type in a scope. And "symbol" is already taken — the emitter uses it for a **linker** symbol,
which is a different thing entirely. A word that means two things in one codebase is worse than a
word nobody likes.

**Clipped fields**, all of them now spelled out: `name_len` → `name_length`, `params` →
`parameters`, `pos` → `position`, `receiver_len` → `receiver_length`, `type_params` →
`type_parameters`, `instance_args` → `instance_arguments`.

## Where the rule stops, deliberately

**Fields and functions must use the whole word. Short-lived locals need not.**

A field crosses files, so an abbreviation in one costs every reader who meets it somewhere else. A
local named `sig` inside a twelve-line function has its declaration on screen with its use, and a
rule reaching that far is a rule people route around. `let sig: Node = self.nodes[item.c];` stays.

Two words are the real words in this language and are not clips: **`len`**, which is the builtin, and
**`ptr`**, which is what a pointer is called in the LLVM IR this compiler emits.

## What the test checks, and what it cannot

**Checks:** that every one of the six families still has its `find_<thing>`; that the six clipped
spellings the audit removed have not returned; that no field in `types.bx` is a clipped word or ends
in one.

**Cannot check:** whether a *new* concept picked a good word. That is a judgement, and the test
would have to know what the concept is. What it does instead is make the existing families
unbreakable, so drift has to start somewhere new rather than eroding what is already right.

It also cannot see prose or emitted IR, and does not try — comments and string literals are stripped
before it looks. The IR in `emit.bx` is full of `%tmp` and `ptr` because that is LLVM's language, not
Burxt's.

## The lesson worth keeping

**An audit finds a thing once.** The `find_sym` inconsistency survived because every reader who met
it was busy with something else, and there was no statement to measure it against. The fix that
matters is not the rename — it is the eleven lines of test that make the rename permanent.

The same shape as `spec/M9-PERFORMANCE.md`'s ratchets and the keyword-currency check in
`the_guide_and_examples_are_linked_and_compile`: **if it is worth fixing twice, it is worth a test
the second time.**
