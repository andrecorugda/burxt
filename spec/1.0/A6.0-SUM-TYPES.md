## 0. Why now

Sum types are the single largest capability gap between Burxt and a
self-hosted compiler. A lexer's `Token` is a sum type; so is every AST node.
They are also **not heap-blocked** — a tag plus an inline payload lives on the
stack, and the v0.0.12 aggregate ABI already knows how to pass and return such
a value. So this is buildable now, ahead of M1.

## 1. Declaration

```burxt
enum Token {
    Plus,
    Minus,
    Number(Int),
    Name(String),
}
```

- Variants are either **unit** (`Plus`) or carry **positional payloads**
  (`Number(Int)`, `Pair(Int, Int)`).
- Declarations are hoisted like records and interfaces: any order.
- Nominal, like records: two enums with identical variants are different types.

## 2. Construction — namespaced, never bare

```burxt
let t: Token = Token.Plus;
let n: Token = Token.Number(42);
```

The variant is always qualified by its enum. Bare `Plus` is refused. Reasons:
a bare name would collide across enums, would shadow variables, and would make
the reader guess which type is meant — against "one obvious way." `Token.Plus`
reads as plain English and reuses the existing `.` token, so no new grammar
ambiguity is introduced.

## 3. Matching — exhaustive, and that is the point

```burxt
match tok {
    Plus => { print("plus"); }
    Minus => { print("minus"); }
    Number(n) => { print(n); }
    Name(s) => { print(s); }
}
```

- Arms are `Variant => block` or `Variant(bindings) => block`. Inside the arm,
  each binding is a normal immutable local scoped to that arm.
- The variant name in a pattern is **unqualified** — the matched value's type
  already says which enum it is, so requiring `Token.Plus` there would be noise
  rather than clarity. (Construction is qualified because there is no context
  to infer from; patterns have context. The asymmetry is deliberate.)
- **A match must cover every variant.** A missing variant is a compile error
  that *names the ones left out*. This is the whole feature: add a variant to
  an enum later and every incomplete match becomes a compile error pointing at
  what to handle, instead of silently taking a default path.
- Duplicate arms are an error; so is naming a variant that does not exist.
- `match` is a **statement** in this cut, not an expression.

## 4. Layout (codegen)

A tag plus an inline payload area: `{ i64 tag, [N x i64] payload }` where `N`
is the largest payload slot count across variants (0 → tag only). Every payload
field is 8 bytes because payloads are scalars (§5), so slots need no per-field
size computation.

Enums are aggregates, so the v0.0.12 ABI carries them unchanged: `byval`
parameters, `sret` returns, value-copy semantics. `match` lowers to a `switch`
on the tag; payload bindings are a GEP into the payload area plus a load.

## 5. What A6.0 must NOT do

Each is a real feature; each is deferred with a trigger, because none is
required to make a lexer expressible.

- **NO wildcard `_` / `default` arm.** This is the most tempting and the most
  damaging. A wildcard silently absorbs variants added later — the exact
  silent-behaviour-change Burxt refuses everywhere else, and it would defeat
  the one guarantee this milestone exists to provide. *Trigger:* a required
  program is genuinely unreadable without it, at which point the honest form
  is an explicit "these remaining variants, deliberately together" syntax
  rather than a catch-all.
- **NO recursive enums** (a variant carrying its own enum, directly or through
  another). Infinite size without heap indirection. **This is the finding that
  matters for self-hosting: a lexer's `Token` is flat and works today, but an
  AST is recursive, so the *parser* is M1-blocked even though the lexer is
  not.** *Trigger:* M1.
- **NO aggregate payloads** (record, array, or enum inside a variant) in this
  cut — keeps every payload slot exactly 8 bytes and avoids the recursive-size
  question entirely. *Trigger:* after M1 settles indirection.
- **NO nested / destructuring patterns** (`Number(Pair(a, b))`). One level.
  *Trigger:* aggregate payloads exist.
- **NO guards** (`Number(n) if n > 0 =>`). They interact with exhaustiveness —
  a guarded arm cannot be proven to cover its variant, so exhaustiveness would
  silently weaken. *Trigger:* only with a story for how coverage is still
  proven.
- **NO match as an expression.** Requires every arm to agree on a type and
  interacts with the return-path prover. *Trigger:* a required program needs a
  value out of a match.
- **NO `==` on enums.** Same reasoning as records: field-wise comparison
  semantics are undecided. Match instead. *Trigger:* with record equality.
- **NO generics** (`Option<T>`, `Result<T,E>`). Generics are their own
  milestone. `Option` and `Result` are the motivation for it, but a
  hand-written monomorphic enum works until then.
- **NO integer-valued / C-style enums** with explicit discriminants. Tags are
  the compiler's business until FFI needs otherwise.

## 6. Deliverables

1. `enum` declaration, hoisted, nominal; unit and scalar-payload variants.
2. `Enum.Variant` and `Enum.Variant(args)` construction, arity- and
   type-checked like a call.
3. `match` statement: unqualified variant patterns, payload bindings scoped to
   the arm, `switch`-based lowering.
4. **Exhaustiveness checking**, naming every missing variant.
5. Enums flow through the existing ABI: locals, parameters, returns.
6. Tests, rejection-weighted:
   - construct and match every variant shape; payload values bind correctly;
     enums as parameters and returns; a `while`+`match` loop.
   - **rejections**: non-exhaustive match (naming the missing variants);
     duplicate arm; unknown variant; wrong payload arity; wrong payload type;
     bare unqualified construction; recursive enum; aggregate payload;
     `_` wildcard (rejected with the reason, so the deferral is enforced).

## 7. The acceptance program

When this compiles and runs, A6.0 is done — because it is the shape of a real
lexer's inner loop:

```burxt
enum Token { Plus, Number(Int), End }

function describe(t: Token) -> Int {
    match t {
        Plus => { return 1; }
        Number(n) => { return n; }
        End => { return 0; }
    }
}
```
