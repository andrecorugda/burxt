## 0. Why now
Burxt currently cannot branch or loop. Every downstream feature — real programs,
the standard library, self-hosting the compiler — assumes control flow. It is the
single largest capability gap. It is also mostly mechanical, so it carries low
design risk.

## 1. What ships
- **A real `Bool` type.** Currently there is none. `true` / `false` literals.
- **Comparison operators** producing `Bool`: `==`, `!=`, `<`, `<=`, `>`, `>=`.
  Per the correctness family: comparison is only between the *same* type. `Int == Int`
  and `Decimal<2> == Decimal<2>` are fine; `Int == Decimal<2>` is a compile error
  (no coercion). Comparing different-scale decimals is an error, exactly like `+`.
- **Boolean operators**: `&&`, `||`, `!`, with short-circuit evaluation for `&&`/`||`.
- **`if` / `else`**: `if <bool-expr> { ... } else { ... }`. The condition MUST be
  `Bool` — no truthiness, no `if 0`, no `if some_pointer`. A non-Bool condition is a
  compile error ("`if` condition must be Bool, found Int"). `else` is optional;
  `else if` chains by nesting.
- **`while`**: `while <bool-expr> { ... }`. Same Bool-only condition rule.
- **`return`**: already exists for methods; generalize to functions and ensure it
  works from inside `if`/`while` bodies (early return).
- **Blocks and scoping**: `{ ... }` introduces a lexical scope. Bindings declared
  inside a block do not escape it. Shadowing rules follow the existing correctness
  stance (no silent redefinition in the same scope).

## 2. Deliberately NOT in A5.0 (deferred, with triggers)
- **NO `for` loops.** `while` is sufficient for Turing-completeness. `for` needs
  iterators/ranges, which need collections (A4.4). Trigger: after collections exist.
- **NO `match`/pattern matching.** This is the exhaustiveness feature from the North
  Star and it needs sum types to be meaningful. Trigger: when sum types (enums) land.
  (`if`/`else if` covers branching until then.)
- **NO `break`/`continue`** in the first cut. Add immediately after if a real program
  needs them (they are cheap), but keep A5.0 minimal: a `while` with a boolean guard
  is complete. Trigger: first program that reads badly without them — likely soon,
  so this is a "fast follow," not a deep defer.
- **NO ternary `?:` expression.** `if` is a statement; expression-if can come later
  if warranted. No C-style ternary — it fights readability.
- **NO truthiness of any kind.** Conditions are Bool, full stop. This is a
  correctness-family commitment, not a temporary limitation.

## 3. Typechecking rules
- `if`/`while` condition: must have type `Bool`, else error naming the found type.
- Both branches of an `if` are typechecked; branch bindings are scoped to their branch.
- `return e` must match the enclosing function's declared return type (reuse existing
  method-return checking).
- Comparisons: same-type operands only; result type `Bool`.
- `&&`/`||`: both operands `Bool`, result `Bool`.
- Short-circuit is a codegen concern but is *observable* (a `&&` must not evaluate its
  right side if the left is false) — so it is specified, not optional.

## 4. Codegen (LLVM)
- `Bool` → LLVM `i1`.
- `if` → conditional branch (`br i1`) to then/else basic blocks, joining at a merge
  block. Standard.
- `while` → header block (evaluate condition), body block, exit block; back-edge from
  body to header. Standard.
- `&&`/`||` → short-circuit via basic blocks (evaluate LHS, conditionally skip RHS),
  not bitwise-and of both sides. The observable no-eval-RHS behavior requires the
  block form.
- Comparisons → `icmp` for Int/Bool; for `Decimal<S>` compare the scaled i64s directly
  with `icmp` (same-scale guarantee means the raw integers are directly comparable —
  no rescaling needed).

## 5. Deliverables checklist
1. `Bool` type, `true`/`false` literals (lexer, ast, typeck, codegen).
2. Comparison operators, same-type rule, `Bool` result.
3. `&&`/`||`/`!` with short-circuit codegen.
4. `if`/`else`/`else if` (parser, typeck condition-is-Bool, codegen basic blocks).
5. `while` (same).
6. Block scoping; early `return` from inside control flow.
7. Tests, weighted to rejections:
   - branching and looping produce correct values (a `while` loop summing, an `if`
     selecting);
   - short-circuit is observable (RHS with a visible side effect is skipped);
   - **rejections**: non-Bool condition (`if 5`); cross-type comparison
     (`Int == Decimal<2>`); different-scale decimal comparison; `&&` on non-Bool.
   - each rejection reads as advice.

## 6. Fibonacci is the acceptance program
When this compiles, runs, and prints the right sequence, A5.0 is done:
```burxt
function fib(n: Int) -> Int {
    let mutable a: Int = 0;
    let mutable b: Int = 1;
    let mutable i: Int = 0;
    while i < n {
        let next: Int = a + b;
        a = b;
        b = next;
        i = i + 1;
    }
    return a;
}
```
It exercises: while, comparison, mutable locals, arithmetic, early-ish return, and
function calls together. If fib runs, the language can express algorithms.
