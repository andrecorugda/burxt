# Reference

Everything the language has, in tables. Generated by reading the compiler, not by memory —
if something is missing here it is probably missing from the language too.

## Keywords

| | | | |
|---|---|---|---|
| `let` | `mutable` | `function` | `return` |
| `if` | `else` | `while` | `break` |
| `continue` | `match` | `record` | `enum` |
| `interface` | `implement` | `dynamic` | `external` |
| `region` | `pure` | `tail` | `print` |
| `self` | `true` | `false` | `as` |

Reserved but not yet used: `for`, `is`, `interface`.

**Contextual markers** — `allocates`, `requires`, `ensures`, `decreases`, `old`, `result`.
`allocates` is **optional and inferred** since v0.0.142; writing it is still legal and still
checked. Every one of these may also be used as an ordinary name.
These are only special where they appear (on a signature, inside a clause), so a variable
may still be called `ensures` anywhere else.

**Names the language owns**, which a program may not declare: `print`, `len`, `byte_at`,
`push`, `truncate`, `substring`, `to_string`, `read_file`, `write_file`, `argument`,
`argument_count`, `divide_floor`, `divide_toward_zero`, `remainder`, `old`, `result`, `main`, `exit`.

## Types

| Type | What it is |
|---|---|
| `Int` | Signed 64-bit. Traps on overflow, never wraps. |
| `Bool` | `true` / `false`. No coercion to or from anything. |
| `String` | Bytes, NUL-terminated. `len` counts bytes. |
| `Decimal<S>` | An integer scaled by `10^S`, exact. `S` up to 18. |
| `Decimal<S, R>` | The same, carrying a rounding contract: `RoundHalfEven` or `RoundHalfUp`. |
| `[T; N]` | Fixed array. The length is part of the type. Bounds always checked. |
| `[T]` | Growable array. Lives in a region. Bounds always checked. |
| `dynamic Trait` | A interface object: a value plus the interface's method table. |
| `CInt`, `CDouble` | C's widths. Only in `external function` signatures. |

## Operators

| Operator | On | Notes |
|---|---|---|
| `+` `-` | Int, Decimal (same scale), String (`+` only) | Scales must match; a contract on one side is carried into the result, two different contracts are refused |
| `*` | Int, Decimal × Int, Decimal × Decimal | Mixed Decimal scales need a rounding contract |
| `/` | Decimal only | Always needs a rounding contract. `Int / Int` is refused |
| `==` `!=` | Any two values of the same type | One equality, no coercion. Strings compare by bytes |
| `<` `<=` `>` `>=` | Int, Decimal, String is refused | Same type both sides |
| `&&` `\|\|` | Bool | Short-circuit: the right side runs only if needed |
| `!` | Bool | |
| unary `-` | Int, Decimal | Checked, like every other arithmetic |
| `+=` `-=` `*=` | Anything the long form allows | Sugar: `x += e` IS `x = x + e` by the time it is checked. Works on a name, a field, and an array element. There is deliberately no `++` |

## Builtins

| Call | Answers | Needs a region? |
|---|---|---|
| `print(x)` | — | No |
| `len(xs)` | `Int` — elements, or bytes of a String | No |
| `byte_at(s, i)` | `Int` | No |
| `substring(s, from, count)` | `String` | **Yes** |
| `to_string(x)` | `String` | **Yes**, except of a `Bool` |
| `push(xs, v)` | `Int` — the new length | **Yes** (the array is in one) |
| `truncate(xs, n)` | `Int` — the new length | No |
| `read_file(path)` | `String` | **Yes** |
| `write_file(path, text)` | `Int` — bytes written | No |
| `argument(n)` | `String` | No |
| `argument_count()` | `Int` | No |
| `divide_floor(a, b)` | `Int` — rounds toward -∞ | No |
| `divide_toward_zero(a, b)` | `Int` — rounds toward zero | No |
| `remainder(a, b)` | `Int` | No |

## Shorthands

The whole list — Burxt has few on purpose, and each one is sugar over something it already
means, not a second way to mean it.

| Written | Means |
|---|---|
| `$19.99` | `19.99` as a `Decimal<2>`. The `$` is documentation |
| `8.25%` | `0.0825` as a `Decimal<4>` |
| `"total: {amount}"` | `"total: " + to_string(amount)` — and in a `print`, the pieces go out in order with nothing built |
| `x += e` | `x = x + e`. Also `-=` and `*=`, on a name, a field, or `xs[i]` |
| `P { x, y }` | `P { x: x, y: y }` — a field taking a variable of the same name |
| `f();` | a call kept for its effect, with no binding |
| `function (self) m()` | `function (self: Type) m()` — inside `implement Trait for Type`, where the header already said which type |
| `P { x: 1, }` | a trailing comma, anywhere a list is written, so adding an item is a one-line diff |
| `let x = e;` | `let x: T = e;` where `T` is `e`'s type. Arrays are the exception — a literal does not say fixed or growable, so they name their type |
| `for x in xs { }` | `let mutable i = 0; while i < len(xs) { let x = xs[i]; i = i + 1; ... }` — `xs` must be a name or a field path |
| `f(x)?` | `match f(x) { Error(e) => return Error(e), Ok(v) => v }` — the failure variant found by name, and never converted |

Also not present: block comments (`/* ... */`) — line comments only, so there is no nesting
rule to get wrong, and every editor will `//` a selection for you. Nor multi-line string
literals: a literal spanning lines makes its own indentation part of the data, which is the
one thing that surprises everybody about them. Use `\n` and `+`.

Also not present: `for i in 0..n` (a range is a second construct, and `while i < n` says it),
and `for x in text` (a String is bytes — `byte_at` says BYTE so the byte-versus-character
question cannot hide).

Not present, each for a reason: `x++` (an expression with a side effect), `a ? b : c` (`if`
as an expression would make it redundant), arrow functions (they are closures, and captured
state needs an owner — see [Memory](04-memory.md)), and `a ? b : c`.

## Generics

```burxt
function identity<T>(x: T) -> T { return x; }
function first<T>(xs: [T]) -> T { return xs[0]; }

print(identity(3));          // T = Int, inferred from the argument
print(identity("text"));     // T = String — a second function in the object file
```

One definition, **one copy per type that uses it** (monomorphisation). No boxing, no
vtable, no runtime type information: a `Decimal<2>` inside a generic is still a scaled
i64. A generic nobody instantiates emits nothing.

A type parameter with **no bound** can be stored, copied, passed and returned — nothing
else, because nothing else is knowable without the signature saying so. A **bound** says
what more is allowed:

```burxt
function largest<T: Ordered>(a: T, b: T) -> T { if a > b { return a; } return b; }
function same<T: Equatable>(a: T, b: T) -> Bool { return a == b; }
function describe<T: Priced>(item: T) -> String { return item.label(); }
```

| Bound | What it allows | Which types have it |
|---|---|---|
| `Ordered` | `<` `<=` `>` `>=` and `==` `!=` | `Int`, `Decimal<S>` — the types `<` works on |
| `Equatable` | `==` `!=` | `Int`, `Bool`, `String`, `Decimal<S>` |
| any declared trait | that trait's methods, dispatched **statically** | any type that implements it |

The **body is checked against the bound**, not against each instantiation — so adding a `>`
inside a generic is a compile error until the signature says so, rather than a silent
narrowing of every caller. And the bound is checked where the type argument is chosen, naming
the parameter and the fix. One bound per parameter; `where` clauses arrive if one is ever not
enough. Type arguments are
inferred from the arguments; a parameter that appears only in the return type cannot be
inferred and is refused.

Enums are generic too, and that is where it pays:

```burxt
enum Option<T> { None, Some(T) }
enum Result<T, E> { Ok(T), Error(E) }

let found: Option<Int> = Option.Some(3);
match found {
    None => { print("nothing"); }
    Some(n) => { print(n); }
}
```

`Option<Int>` and `Option<String>` are different types with different layouts. Both live in
`lib/` — [`option.bx`](../../lib/option.bx) and [`result.bx`](../../lib/result.bx) — as
ordinary Burxt with no compiler support beyond generics.

**There is no null.** Absence is a type, `match` makes you handle it, and there is no `unwrap`
because "give me the value and abort" is null with extra steps.

`?` is the shortcut, in a function that itself answers with a failure:

```burxt
function average(a: Int, b: Int, n: Int) -> Result<Int, String> {
    let mean = divide(a + b, n)?;      // the value, or return the Error from here
    return Result.Ok(mean);
}
```

It recognises a failure by the **variant name** — `Error` or `None` — never by the enum's own
name, which is what lets `Option` and `Result` be library types. Any enum with exactly two
variants, one called `Error` or `None`, gets it.

It does **not convert** between error types: if the callee fails with a String and you fail
with something else, write the `match`. Somebody has to decide what the caller's failure means,
and that decision does not belong to an operator.

Records are generic too, which is what containers are for:

```burxt
class Stack<T> { items: [T] }

function (mutable self: Stack<T>) push_one(item: T) -> Int {
    return push(self.items, item);
}

let mutable ints: Stack<Int> = Stack { items: [] };
let n = ints.push_one(5);
```

The receiver names the record's parameters — `self: Stack<T>` — and each instantiation gets its
own copy of every method. A method may use its type's parameters and declares none of its own.
Type arguments come from the annotation, or are inferred from the field values when those say
enough (`Holder { one: 1 }` needs no annotation; `Stack { items: [] }` does).

Not yet: generics in the Burxt-hosted compiler. See [`spec/M7-GENERICS.md`](../../spec/M7-GENERICS.md).

## Signature grammar

```
[pure] function name(params) -> Type [allocates] [requires E] [ensures E] [decreases E] { body }
[pure] function (self: Type) name(params) -> Type [allocates] [clauses] { body }
       function (mutable self: Type) name(...)                // writes through to the caller
external function name(params) -> Int | CInt;                 // returns only Int or CInt
external function name(amount: Decimal<S> as scaled) -> Int;  // money crosses as its integer
```

## Runtime failures

All exit **70**, all named, all on stderr.

| Message | When |
|---|---|
| `arithmetic overflow — the exact result no longer fits in the value range` | `+ - *` on Int or Decimal |
| `index N is out of bounds — this array holds M` | Any index the compiler could not prove |
| `byte index N is out of bounds — this string has M` | `byte_at` past the end |
| `substring(s, N, M) does not fit` | A slice past the end |
| `truncate(xs, N) — this array has M elements` | Truncating to more than there is |
| `region memory exhausted — this build reserves 1 GB per process` | The bump pointer ran out |
| `` `requires E` failed in `f` `` | A precondition was false |
| `` `ensures E` failed in `f` `` | A postcondition was false |
| `` `decreases E` did not decrease on a recursive call to `f` `` | The measure did not shrink |
| `` `decreases E` is negative in `f` `` | The measure went below zero |
| `division by zero` / `divide_floor(...) by zero` | Integer division builtins |
| `divide_toward_zero(...) overflowed` | The most negative Int divided by -1 |
| `argument(N) does not exist` | Reading an argument that was not given |
| `cannot open file for reading` / `for writing` | `read_file` / `write_file` |
| `this Int cannot cross as a C double exactly` | Beyond 2^53 at the boundary |
| `this value does not fit in a C int` | An `Int` too large for a `CInt` parameter |

The Burxt-written compiler's own runtime reports the same failures with the index, the
length **and the source position**: `index -1 is outside an array of 1 (at byte 118938)`.
That extra detail is what found the short-circuit bug in v0.0.73, and stage-0 will grow it.

## Compile-time refusals worth knowing

| It says | Because |
|---|---|
| `scales must match. Burxt does not silently rescale money` | Addition combines like quantities |
| `these are two different rounding contracts` | `+` on `RoundHalfEven` and `RoundHalfUp` — picking one would be silent |
| `needs a rounding contract: the exact product has N decimal places` | The result cannot land exactly |
| `only one equality, no coercion` | Comparing two different types |
| `is already declared — Burxt does not allow shadowing` | A second `let` of the same name |
| `allocates, so it needs a region: there is none open here` | Building a value outside a region |
| `cannot return this: it allocates` | Escaping storage that would not outlive the call |
| `this match has no arm for X` | Exhaustiveness — there is no wildcard |
| `` `implement P for B` is missing the method `label` `` | Conformance is complete or it is not — no default bodies |
| `a `pure` function may not …` | Purity is a checked claim |
| `only Int or CInt may cross the C boundary as a return` | Ownership of C memory is not describable |
