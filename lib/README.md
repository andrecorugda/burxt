# The Burxt standard library

```burxt
use "lib/string.bx";
use "lib/files.bx";
use "lib/os.bx";
```

Written in Burxt, from the same builtins any program has. Nothing here is privileged: every
function could have been written by the program that uses it, and the point is that it was
written **once, carefully**, instead of forty times.

| [`result.bx`](result.bx) | `Result<T, E>` — failure as a type. `result_or`, `result_is_ok`, `result_is_error`, **`result_context`** *(`"reading the config: no such file"` — `String` errors only, and the header says why a generic `E` cannot be)*, **`option_ok_or`** *(an absence, given a reason)*. All four stop with exit code **70**, the same code the runtime uses, and say `burxt panic:` so a reader knows which layer noticed. They sit next to the type that exists to avoid them **on purpose** — both options in front of a reader at once. A `requires` clause beats `assert_that` wherever one fits, because it is part of the signature |
| [`decimal.bx`](decimal.bx) | **`money_split`** — $100.00 three ways is `[$33.34, $33.33, $33.33]`, largest-remainder, and **the parts sum to the total exactly on every input**; the fixture asserts that over 5,213 splits rather than on examples. Negatives mirror positives, so a credit note cancels the invoice line for line · per-scale `abs`, `sign`, `is_zero`, and `decimal2_round_to`/`decimal2_percent_of` at **half-even**, written in Int where the tie rule is four visible lines · the unscaled integer, reached by `decimal2_cents`/`decimal4_ticks`/`decimal6_ticks`/`decimal7_ticks`. **There is no Decimal→Int cast in this language** (`as scaled` is FFI-only), so each is an exact bit-descent binary search, the trick `vector.bx` already uses. **A scale cannot be a type parameter**, hence per-scale — except `min`/`max`, which `math_min`/`math_max` already give generically over `Ordered` at every scale, and which are deliberately not repeated here |
| [`array.bx`](array.bx) | **asking:** `array_contains`, `array_index_of`, `array_is_sorted`, `array_count_of`, `array_equals`, `array_binary_search`, `array_min`/`max`/`first`/`last`, `array_sum_int`/`sum_money` · **new arrays:** `array_copy`, `array_slice` *(end-exclusive)*, `array_concat` · **changing:** `array_swap`, `array_reverse`, `array_sort`, `array_fill`, `array_extend`, `array_remove_at`, `array_insert_at`, `array_dedup` *(adjacent only — it is `uniq`)* · **higher order, over [`fn.bx`](fn.bx):** `array_map`, `array_filter`, `array_fold`, `array_any`, `array_all`, `array_position`, `array_retain`, `array_partition`, `array_sort_by` *(a stable merge sort)*. **`mutable xs: [T]` in the signature means the call changes YOUR array**, and **assigning an array does NOT copy it** — `array_copy` is why |
| [`fn.bx`](fn.bx) | The four interfaces that stand in for a function value: `Mapper<T, U>`, `Predicate<T>`, `Folder<T, A>`, `Comparer<T>`. **Burxt has no closures by decision** — `dynamic Trait` was already a function value and A9 made it generic, which closed A10 without building it. One file because an interface may be declared **once** in a program, so two modules cannot each have their own `Predicate`. State is a field, not a capture |
| [`math.bx`](math.bx) | `INT_MAX`/`INT_MIN`, `math_min`/`max`/`clamp` (generic over `Ordered`), `math_abs`, `math_sign`, `math_pow`, `math_isqrt`, `math_gcd`, `math_lcm`, and four families for overflow: `+` traps, `math_checked_*` answers `None`, `math_saturating_*` clamps to the bound, `math_wrapping_*` discards the carry |
| [`hash.bx`](hash.bx) | **Cryptographic:** `sha256`, `sha512`, `hmac_sha256`, `hmac_sha512`, `pbkdf2_sha256` — plus `hash_hex` and `hash_equals_constant_time`, whose name is its warning · **NOT cryptographic, and the header says so before anything else:** `crc32` *(promoted out of `tests/pass/bits.bx`, §E4)*, `fnv1a_32`, `fnv1a_64`. **Using a checksum for a token is a security bug** and the two groups are labelled rather than left to be inferred. A `_text` suffix is the same function over a String. **The vectors are the test and they are pinned**: FIPS 180-4 for both SHA-2s including one million `a`, all seven RFC 4231 cases for both HMACs including the 131-byte key that must be hashed first, and the published PBKDF2-HMAC-SHA256 set — *plus* PBKDF2 checked against `hmac_sha256` by definition, so a remembered constant cannot be the only authority. **`Int` is i64 and `+` traps**, so u32 rides inside it and is masked after each add while u64 carries by hand through `hash_add_wrapping_64`; A7's `u32`/`u64` are boundary-only and cannot be used as arithmetic types. Measured over 1 MB: SHA-256 19 ms, SHA-512 12 ms, CRC-32 19 ms, FNV-1a 7 ms, and **constant memory beyond the input** — the message is never copied, only the final block is built. **What is deliberately absent:** AES, RSA, curves, TLS, Argon2/scrypt/bcrypt (§E5 — bind, do not hand-roll), a CSPRNG for salts (§E3), and any way to erase a secret (§E6) |
| [`random.bx`](random.bx) | A **seeded** generator and the name says so: `random_from(seed)`, never a bare `random()` — reproducible on purpose, which is right for tests, shuffles and sampling and **wrong for keys**. `Random` then has `next` (raw 64 bits), `next_below` *(exclusive)* and `next_between` *(INCLUSIVE of both ends, so a range can name `INT_MAX`)*; `random_shuffle` and `random_choice` are free functions because a method may not declare its own type parameters. **xorshift64 (13, 7, 17)**, chosen because it is pure xor and shifts and so cannot trap where Burxt's `+` and `*` refuse to overflow; its F2-linearity is named in the header rather than left to be discovered. No modulo and therefore no modulo bias — masked rejection. Three answers a caller would guess the other way: `next_below(0)` and `next_between(5, 4)` are **refused by contract** rather than answering 0 or swapping, `random_choice([])` is `None` because absence of an element is a real answer where absence of a number is not, and a shuffle of 0 or 1 elements **draws nothing**. Seed 0 is remapped (xorshift's fixed point) and every generator is **warmed up** eight draws, because from seed 1 the first raw output is thirty bits |
| [`secure.bx`](secure.bx) | **The other generator, and it sits here so the contrast is one row away.** `secure_random_bytes` reads the OS entropy pool through `getentropy` — the portable spelling; `getrandom` is Linux-only and broke the macOS runner — and **loops past its 256-byte cap** so a caller never meets that number. The return value is CHECKED: a failed call answers `Option.None`, never the buffer, because on failure `malloc`'s leftovers would be handed back as a key. Then `secure_random_int_below` *(rejection sampling, so no modulo bias)*, `secure_uuid_v4` *(122 random bits; the version nibble is `4` and the variant one of `8`/`9`/`a`/`b`, both asserted over 200 draws)*, `secure_token_hex` and `secure_token_urlsafe` · **B4:** `string_equals_constant_time` and `bytes_equals_constant_time` — `==` on Strings stops at the first differing byte and **leaks the answer through timing**, so these fold every byte into one accumulator and fold the LENGTH in rather than returning early on it. The name is spelled out for the same reason `divide_floor` is. **Measured over 30 million comparisons of two 32-byte strings:** `==` takes 20 ms when they differ at byte 0 and 400 ms when they differ at byte 31 — that 20× ratio *is* the leak — while these take 940 ms and 920 ms, two columns that are noise apart · **E6, and this is the file to read it in: a secret cannot be zeroed.** There is no `zeroise`; a value lives until its region closes and its bytes are not scrubbed. The shortest-lived region you can put it in is the only mitigation the language offers, and the header says so at length · **E5 is deliberately absent** — no AES, ChaCha20, RSA or Argon2. Bind a reviewed C library; a subtly wrong cipher produces ciphertext that looks fine |
| [`encoding.bx`](encoding.bx) | `encoding_hex_*`, `encoding_base64_*`, `encoding_base64url_*`, each in four forms: `[Int]` in and out, plus a `_text` twin for a `String`. Encoders take bytes; **decoders answer `Option` and REFUSE rather than guess** — a character outside the alphabet, a length no encoding could produce, padding in the middle, the other dialect's alphabet, and **non-canonical trailing bits**, so `"Zg=="` decodes to `f` and `"Zh=="` is refused rather than decoding to the same byte a second way. Whitespace is refused too, including a trailing newline, which means MIME and PEM need their line breaks stripped first — said out loud rather than discovered. Standard base64 always pads and requires padding; **base64url does not pad** (a `=` is illegal in a JWT) and accepts either. Every RFC 4648 §10 vector is pinned in `tests/pass/encoding_library.bx`, which also round-trips all 256 byte values — a NUL included, since a Burxt String carries its length in a header |
| [`set.bx`](set.bx) | `Set<T: Equatable>` over `Map<T, Bool>` — `set_new`, then methods: `add`, `add_all`, `has`, `remove`, `count`, `items`, `take`, `union`, `intersect`, `difference`, `is_subset_of`, `equals`. **Insertion order, and a re-added element goes to the end.** `union`/`intersect`/`difference` answer a NEW set |
| [`time.bx`](time.bx) | `DateTime` and `Duration`, **UTC only and whole seconds — both said in the header, not guessed**. `time_from_unix`/`time_to_unix` (Hinnant's exact-integer calendar, no table, no float), `time_format_iso`/`time_parse_iso` (RFC 3339; an offset is **refused**, never read as UTC), `time_weekday`, `time_day_of_year`, `time_is_leap_year`, `time_days_in_month`, `duration_seconds`/`minutes`/`hours`/`days`, `time_add`, `time_between`. Dates before 1970 work. **No leap seconds** — unix time has none |
| [`map.bx`](map.bx) | `Map<K, V>` in insertion order, always. `map_new`, then methods: `set`, `get`, `find`, `has`, `remove`, `count`, `is_empty`, `clear`, `merge`, and three views — `keys`, `values`, `entries` *(`[(K, V)]`, which needed A8's tuples)*. All three answer a **fresh** array, so a caller may hold one while the map changes |
| [`json.bx`](json.bx) | `Json` and `Field`, `json_render`, `json_parse`, and the typed readers. **A JSON number is its digits, not a float** — see the header |
| [`html.bx`](html.bx) | `Html` and `Element`, `html_element`/`html_text`/`html_raw`/`html_attr`, `html_render`, `html_document`. **An `Html` value cannot carry an unescaped String by mistake** — `Text` and `Raw` are different constructors and neither is the default, so the one line that waives the rule is the one line a reviewer greps for. **Escaping happens on RENDER, not at construction**: escape eagerly and `Text` holds already-escaped text with nothing in the type saying so, and one function that forgets puts a hole in the page — this way there is exactly one place to be right · **the two holes escaping does NOT cover, both refused by contract:** a tag or attribute NAME is written into the markup as syntax by definition, so `html_is_name` refuses `"div onclick=steal()"` before it can render with perfectly escaped children; and a **void element may not carry children**, because `<br>Rice</br>` is read by a browser as a SECOND `<br>` with the text outside — a wrong answer nothing would report. `'` renders `&#39;` and not `&apos;`, which is XML's spelling. The escape loop is `json_escape`'s, copied rather than re-derived, for the reason recorded there |
| [`bmx.bx`](bmx.bx) | **BMX 0.1** — markdown with one unambiguous reading and a typed hole in it. `bmx_parse` → `[Block]`, `bmx_json` (the AST the format's conformance suite compares), `bmx_to_html` + `bmx_bind` (rendering), `bmx_target_allowed`. **The format lives in its own repository with its own version and its own CI**; this is one implementation of it, and `tests/bmx-conformance/` vendors the suite · **the one property that separates BMX from markdown: it always fails loudly.** `*bold` unclosed, an unterminated fence, `{{ x` with no `}}` — each is an error with a CODE (`BMX-E001`…), never output that looks nearly right. Markdown is designed so nothing is ever a syntax error, which is the opposite of what a refusing compiler can build on · **level 1, and it says so**: slot values are looked up by expression TEXT and nothing here checks a type. It still refuses a slot with **no binding** (never the empty string — that is how a page ships with a missing total) and a link target whose scheme is not `http`/`https`/`mailto` (`javascript:` is an attack escaping cannot touch, because the danger is the scheme) · **level 2 is `bmx_emit_burxt`, and it is a code GENERATOR rather than a renderer — the design, not a limitation.** A `.bmx` becomes a `pure function -> Html` whose slots are ordinary Burxt expressions, and the COMPILER checks them. Measured, all four: a slot naming a missing field is a type error *at the expression*; a slot holding a `Decimal` rather than a `String` is a type error, so the conversion is written in the document where a reviewer sees it; **money that would narrow without a rounding contract is refused inside the view**; and a `javascript:` link target is refused by the generator before a page exists. `examples/bmx/generate.bx` is the command; `the_bmx_generator_hands_the_compiler_a_view_it_can_check` runs every claim. **None of it is implemented in this file** — it is what the language already does to any function · **a BMX document in a Burxt string literal must escape every brace** — `"\{\{ x \}\}"` — because `{` opens an interpolation and a bare `}` closes one. It compiles; it is unreadable, which is why documents live in `.bmx` files. The delimiters do not move for it: `DESIGN.md`, *"The delimiters do not move for an embedded format"* (2026-08-16) |
| [`cgi.bx`](cgi.bx) | `Request` and `Param`, `cgi_request`, `cgi_params`/`cgi_param`, `cgi_decode_path`/`cgi_decode_form`, `cgi_respond`/`cgi_respond_html`, `cgi_status_text`. The interface every web server has spoken since 1993 — request in environment variables and on stdin, response on stdout — so **a Burxt binary behind nginx serves dynamic pages with no listener, no sockets and no concurrency** · **malformed input is refused, never repaired**: `%zz`, a `%` with fewer than two hex digits after it, and a parameter with no `=` all answer `None`, because "helpfully" decoding `%zz` as the literal text is a silent wrong answer in the layer where user input first meets the program. A **completely empty** query is not malformed and answers an empty list; a trailing `&` is what a real form sends and is skipped · `cgi_param` takes the **FIRST** of a repeated name and says so out loud, because reading one value where a proxy reads the other is how parameter pollution works · `+` is a space in a form and an ordinary byte in a path, which is why decoding is two named functions · **`Content-Length` is `len(body) + 1`**: `print` is the only way out of a Burxt program and it appends a newline, so that byte is on the wire — and therefore **a body is TEXT**; a PNG through this file is corruption, and that is a compiler gap rather than a library one |
| [`csv.bx`](csv.bx) | Read and write, RFC 4180 **with every deviation named in the header**. `csv_parse`/`csv_render`, `csv_parse_delimited`/`csv_render_delimited` over `CSV_COMMA`/`CSV_SEMICOLON`/`CSV_TAB` and LF or CRLF, `csv_quote`, `csv_column`, `csv_widths_agree`, and `CsvRow` with `count()`, `at(i) -> Option<String>` and `offset` *(the byte the record began at — a byte and not a line, because a quoted newline puts one record on several)*. **Parse, write, parse, write is the test**, and it is in `tests/pass/csv_library.bx`. The decisions a reader will want to check: a **byte-empty line is skipped** rather than becoming a record of one empty field, so the newline every file ends with adds no phantom record — and `csv_render` therefore writes a one-empty-field record as `""`; a **lone CR is data**, only `\r\n` and `\n` end a record; **bytes inside quotes are kept exactly**, CRLF included, which is what makes the round-trip byte-exact; a **leading UTF-8 BOM is stripped** because Excel writes one and it otherwise becomes part of the first header's name; **junk after a closing quote is refused**; a field is **bytes** — nothing is trimmed, parsed or type-guessed. **A ragged row is kept by `csv_parse` and REFUSED by `csv_parse_rectangular`, never padded**: padding invents an empty String in a column that may be the amount |

There is **no recursive delete**: `rm -rf` on a computed path is the mistake a library must not hand you, and `file_walk` + `file_delete` in reverse is the three-line replacement a reviewer can see |
| [`path.bx`](path.bx) | `path_join`, `path_basename`, `path_dirname`, `path_extension`, `path_stem`, `path_is_absolute`, `path_normalise`. **POSIX only and it says so** — `/` is the separator, a backslash is an ordinary byte, and Windows is 1.1's problem. Purely lexical: nothing here touches the filesystem, so `normalise` does **not** resolve symlinks and `a/b/..` is not always `a`. Three answers a caller would guess the other way: `path_join("a", "/b")` is `"a/b"` and does **not** let the absolute right-hand side discard the left the way Python and Rust do; `path_extension("archive.tar.gz")` is `"gz"`, one extension, no dot; `path_normalise("../..")` keeps both — **a relative path never loses a leading `..`**, while `/..` is `/` because the kernel says so |

Threshold from `BURXT_LOG`, case-insensitive and space-trimmed: `off`/`none`/`silent`, `debug`, `info`, `warn`/`warning`, `error`. **Unset means WARN** — quiet in normal running, and an error is never silently lost. **An unknown value means DEBUG, never off**: a typo must show too much rather than too little, and `log_env_problem()` says so in words. Timestamps are `lib/time.bx`'s ISO-8601, so UTC and whole seconds |

## Why it exists

Two reasons, and the second is the real one.

**Convenience**: splitting a string, appending to a file and listing a directory are things
every program needs and none should re-derive.

**Safety at the boundary**: a C function's ownership is something Burxt cannot check, and
**every program that writes `external function fopen` itself is a program making a promise
nobody verified.** Here the promise is made once, in the open, with the reasoning next to it.

That paragraph used to say `opendir`, `getenv` and `fopen` were *"out of reach directly"* and
that the shell was the only way through. **The pointer wall opened in v0.0.196**: `-> CPointer`
is legal, `c_is_null` and `c_string_at` read one, `c_bytes_at` reads a counted buffer, and all
three of those functions are now called directly by `files.bx` and `os.bx`. What is still out
of reach is a **struct behind a pointer** — `readdir`'s `d_name`, `stat`'s `st_size`,
`nanosleep`'s `timespec` — so `file_list_directory` still shells out to `ls` and `os_sleep`
still calls `usleep`. Each of those choices is now argued at the function rather than assumed
from a blanket rule.

## What it does not hide

- **`file_read` of a missing file ends the program**, exit 70, and of a directory exhausts the
  region. It does not answer `""`. `file_read_maybe`, `file_size` and `file_walk` answer
  `Option`; `string_to_int("abc")` still answers 0 and `string_parse_int` is its honest twin.
  `file_list_directory` answers `[]` for a directory that is not there, which is the one place
  the old shape survives, and it is named in the file rather than left to be discovered.
- **`file_append` reads the whole file and writes it back**, because the builtin replaces
  rather than appends. Fine for a log line, wrong for a gigabyte, and worth knowing which
  you have.
- **`file_quote` refuses a path containing a single quote** rather than mishandling it. Shell
  quoting has exactly one hole and that is it.
- **Building a large String means chunks**, never an append per byte or per line — this
  project has paid for that three times (v0.0.68, v0.0.77, v0.0.82). `os_read_all` batches
  in 4 KB pieces for that reason.

## Naming

Every function is prefixed with its module — `string_find`, not `find`. There is no `pub` and
no namespacing yet, so a short name would collide with a program's own, and a collision is a
compile error rather than a silent shadow. When modules get namespaces the prefix becomes
redundant and can go.
